## The two divergences, and why they're different shapes

`commit-msg` no longer prints `Genuinely unfilable? git commit --no-verify`. A
bypass advertised by the thing enforcing the rule becomes the habit. The reason
is written above the `if [ -z "$ids" ]` block, so whoever does the next resync
reads it exactly where they'd otherwise "fix" the drift by taking the template.

The `bd setup codex` block is the same class of problem with no such defence.
`harness add` runs it, it appends a duplicate of AGENTS.md's own ledger section
plus a `bd prime` advert, and it says nothing in its output — AGENTS.md just
comes back modified. I caught it only by reading the diff of a run whose purpose
was installing one missing script. There is nowhere to put a comment about text
that isn't there, so this one lives in `bd remember` and nowhere else. Check
`git diff AGENTS.md` after any `harness add`.

Both are filed upstream: **har-uf7** and **har-8on**, in harness-starter, both P1.
Once they land, ccp's copies go back to matching and the drift report gets
quieter by two.

## Mid-thought

`review.sh` had no `*.json` or `*.html` in scope, so `opencode.json` and
`dashboard/index.html` had never been reviewable by the pass that reviews
everything else. Fixed, but it makes me distrust the scope list generally — it's
a suffix allowlist, so the failure mode is always silent omission rather than
noise, and nothing tells you a file was never looked at. A scope that reported
what it *excluded* from a given diff would have caught this years earlier. Didn't
build it; not sure it's worth the output.

The three remaining contract-file reports (`reviewer-design.md`,
`agentic-review/SKILL.md`, `review.sh`) are false alarms of a known kind: filling
in a FILL THIS IN block deletes the marker that would have classified the file as
customised. har-awe is about the starter's own version of this. Worth checking
whether the classifier should look for the *absence* of the marker plus presence
of project-specific content, rather than the marker alone.
