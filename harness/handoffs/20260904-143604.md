# handoff 2026-09-04

Closed ccp-2zi.1 and ccp-2zi.2 — the note model and a rich-text editor on
SwiftUI's own AttributedString TextEditor. Both reviews found real defects and
both times the fix was to change the design rather than patch it; the two traps
are in bd remember.

Was mid-thought on whether markers should be in the text at all. Counting a
known prefix works and is tested, but it is still a decoration the user can put
their caret inside and backspace through, and I never checked what a delete at
offset zero of a list item does — it probably eats the bullet and leaves the
block kind behind. NSParagraphStyle textLists would put markers outside the
text flow entirely and make the question go away; I didn't try it because I
couldn't tell whether SwiftUI's TextEditor honours it, and finding out is maybe
twenty minutes. If markers keep causing trouble in ccp-2zi.9, try that before
adding another counting rule.

Next: ccp-2zi.9 (block kind commands). The editor draws headings, lists and
to-dos correctly but nothing can make one, so the feature can't be judged yet.
ccp-2zi.8 gates all the Craft sync work and wants real API reading, not the
search summary that filed it.

User decisions this session, both explicit and both reversing my proposal:
no UserDefaults text storage at all (Craft is the store, behind NoteStore), and
two-way sync rather than one-way. The both-sides-changed case is still unsolved
and is written into ccp-2zi.8.
