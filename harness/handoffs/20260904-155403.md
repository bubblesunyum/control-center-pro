# handoff 2026-09-04

The scratchpad's direction changed: markdown is the pad's truth now, edited
live-styled by swift-markdown-engine. Spiked and proven on branch
spike/markdown-engine — it renders right at 148pt and takes the keyboard in the
non-activating panel, which was the risk. ccp-dn5 has the state; ccp-xgl is next.

The thing I keep turning over: the block model I reviewed at the start of the
session (NoteDocument and friends, ~900 lines plus 740 of tests) has zero call
sites and never shipped. Three beads built it. Nothing in the review pass caught
that, because a review reads a diff and a diff can't see that nobody calls you.
Worth wondering whether the gate should — an unreferenced public type in CCPKit
is cheap to detect and would have caught this in week one rather than at the
point where deleting it is the plan.

Rejected, and it still tempts me: keeping NoteDocument as the sync-side model
rather than deleting it. It is genuinely good code and the Craft side does need
blocks. But the blocks it needs are (id, verbatim markdown slice) pairs, and
NoteDocument models inlines and marks that would only be re-emitted into
markdown again — which is the exact round-trip the new design exists to avoid.
Deleting it is right. I wanted it not to be.

Two things I did not check and would check first if I picked this back up:
whether MarkdownEngine can make a per-range region inert (isEditable is
whole-view, and ccp-occ's read-only blocks need it — that may be an upstream PR
rather than a styling job), and whether Craft's GET returns byte-stable markdown
for what we PUT. The second decides which side ccp-xgl hashes, and if it
normalises, every block reads as changed forever and the sync never quiets.

Also unrun: the standing review pass. The spike is a branch nobody is merging
yet, so I let it wait — but ccp-s63's deletion and ccp-xgl both want
reviewer-correctness before they land.
