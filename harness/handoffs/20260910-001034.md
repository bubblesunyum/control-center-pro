The thing I kept getting wrong all session, and would warn the next person
about: the two-space boundary marker is real text, and every rule written about
it has to say what happens when the marker ISN'T there. `HardBreak.normalized`
sheds a space-only line on read and Craft strips trailing spaces on write, so a
freshly-opened empty block and a saved one are different strings that must
behave identically. Three of the four bugs the user found were that same gap in
a new place. `bd recall an-empty-block-cannot-hold-a-soft-break` is the related
constraint I hit and could not design around.
