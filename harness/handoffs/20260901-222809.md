# handoff 2026-09-01

Shipped the mail widget (ccp-8lh) — but the thing worth carrying is that
PsymailKit's library lane built clean while exporting *nothing*: every psymail
type is internal, so `swift build` succeeding proved only that it compiled, not
that a host could name anything in it. Two commits over in psymail-mini
(psy-31y, psy-6bj) are the actual seam.

Mid-thought and not chased: the widget's live Google path has never run. Every
screenshot in this session came from `PSYMAIL_FIXTURES=1 scripts/capture.sh`,
which I added to the façade precisely because the capture pass cannot sign in.
So sign-in, token refresh, and the loopback redirect landing back in a
non-activating NSPanel are all unexercised. The correctness reviewer read the
sign-in path and argued it survives panel dismissal (the Task is unstructured
and holds the adapter; `deactivate()` only cancels the tracked refresh) — that
reasoning looked right to me, but reading is not running, and the first real
`Connect` click is where I'd expect trouble.

The one I keep going back and forth on is the path dependency (ccp-lst). It is
correct *right now* — psymail's embed surface changed three times in this
session alone, and each change would have cost a push and a bump. But it means
CCP alone no longer resolves, which is a real cliff for any machine that isn't
this one, and the temptation is to leave it because it never hurts locally. Pin
it the moment PsymailInbox stops moving.

Also worth knowing before touching layout: adding a widget to `standardLayout`
does nothing for anyone who has already run the app — layout.json wins. Cost me
two screenshots to notice. Both traps are in `bd recall`
(new-widget-is-invisible-to-an-existing-layout,
psymailkit-exports-one-type-on-purpose).

Next I'd take ccp-cvi — the README Secrets.plist setup, now unblocked and the
last thing between a fresh clone and a working mail card.
